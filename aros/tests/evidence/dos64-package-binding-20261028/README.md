# DOS64 selected-runtime binding

Staging's production `require_platform_runtime` checks POSIX, stdc, stdcio and
DOS64 against GUI, cold, encrypted-root and native debugger evidence. The
selected DOS64 is included in Platform/Libs. Unit tests exercise a matched set,
missing and mismatched DOS64 evidence independently in each of the four runs,
and an absent selected library. All 19 staging tests pass. These are gate tests,
not native runtime tests or successful bundle assembly.

Hosted service run 9ZONv1mp (inputs PygfQSZl) passes the complete writer/cold
suite, report reverse/export checks, both runtime prerequisite checks, exact
DOS reads, independent host zdb, and unchanged reader member hashes.
Hosted debugger EmvelDKE passes exact label comparison, two lifecycle cycles,
actual missing-security denial, populated L2ARC byte orders/checksum failures,
malformed entry bounds and healthy recovery. All inputs remain unchanged.
Both runs explicitly bind the same corrected DOS64, stdc px9y2jvo, stdcio
uo0iplm_, POSIX j099bkwp and DOS 4CUMjP0r. No new engine build is claimed.

Public-service and label-debugger QEMU runners now snapshot optional stdc,
stdcio and DOS64 inputs at canonical filenames and record their hashes before
mapping them into each private ISO. Shell syntax checks pass; these changes
have NOT yet executed in QEMU because the foreign Bluetooth VM remains live.
No old qualification manifest was retroactively changed. Hosted evidence is
not accepted in place of the existing native package gate.

DOS64 source-snapshot/replay packaging remains outstanding, as do matching
native QEMU acceptance runs. No release bundle was assembled or promoted.
No DUT/user hosted/foreign QEMU session was touched. Retained logs are small;
test pools and runtime copies stay outside git on the external artifact drive.
