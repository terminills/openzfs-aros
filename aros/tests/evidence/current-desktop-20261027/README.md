`5HkSG7Ab`, MetaMake CLI/Manager `2DYgVEWO`, handler `jxfoSGcL`, and acceptance
client `vAeEzG72` with the recorded alpha18c5/private DOS/POSIX platform.

The Manager connected to the real service. Its Simple-view pool query displayed
`public_mirror ONLINE` and capacity values; Wanderer displayed the mounted
`OZPUBLIC` volume and files, including `hello.txt`. `live-pools.png` records that
combined view. `drawer-closed.png` records the drawer closed while Manager
remains open. Manager was then closed through its normal close gadget, not by
terminating Wanderer or the guest. The harness subsequently reported exact
post-UI file readback and final storage PASS.

Tablet input did not initially land at the requested pixel coordinates. The
recorded actions include those attempts; selection and query results were
checked visually before being counted. No KVM or user desktop was involved.

This verifies the current engine with the retained native Manager/handler,
not a new UI implementation, all management operations, stock-SDK compatibility
or physical durability. This particular GUI fixture is not persistent; the
separate writer/cold-reader evidence covers persistence. The run's generated
ISO was removed by its terminal-image cleanup, with hashes retained.
